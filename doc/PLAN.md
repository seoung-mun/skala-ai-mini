# 금융 약관·상품 근거 에이전트 — 진행 계획 (과제 2번)

## 주제
모든 주장에 조항 근거(조항 ID)를 붙이고, 인용 검증으로 환각을 줄이는 약관·상품 질의 에이전트.

## 루브릭 
기능 구현 완성도 30 / 기술 요소 30 / 한계·트레이드오프 20 / 발표 20 / Before-After 실측 +10

## 계획
| 순번 | 영역 | 무엇을 바꾸나 | 추가설명 |
|---|---|---|---|
| 1 | 데이터 | 공개 약관·상품 설명서 5~8개를 조항 단위로 분할, 조항 ID 부여 | 조항 ID가 인용 검증의 기준 |
| 2 | RAG | 조항 단위 임베딩 + 메타데이터(상품, 조항 ID) 검색 | 질의와 가까운 조항을 의미 기반으로 검색 |
| 3 | 그래프 | 질문 유형 라우팅: 약관 근거 / 상품 비교 / 잡담 | 라우팅 정확도를 별도 측정 |
| 4 | 멀티에이전트 | 상품 비교 질문은 상품별 조사를 병렬 서브에이전트로 분리 | 단일 조사 대비 정확도·지연 비교 |
| 5 | 검증 | 인용 검증 노드: 답변 속 조항 ID가 실제 문서에 있는지 코드로 확인 | 실패 시 재작성(최대 N회), 그래도 실패하면 "근거 없음" 응답 |
| 6 | MCP | 문서 조회를 MCP 서버(stdio)로 분리 | 문서 조회 도구만 분리 |
| 7 | 프론트 | Vue 채팅 화면에 SSE 진행 단계 + 인용 조항 표시 | 인용 클릭 시 원문 조항 표시 |
| 8 | 평가 | 골든셋 30~50개, 지표: 인용 ID 실존률 / 근거 지지율 / 비교 질문 정답률 / 비용·지연 | 지지율만 LLM 판정, 나머지는 코드 채점 |
| 9 | Before/After | v1(질문당 검색 1회, 검증 없음) vs v2를 같은 골든셋으로 비교 | 정확도 향상과 지연·비용 증가를 함께 보고 |
| 10 | 한계 | 환각 잔존율, 약관 개정 반영, 문서 범위 정리 | 한계·트레이드오프 항목 대응 |

우선순위: 2, 3, 5, 8, 9번. 4번과 6번은 시간이 모자라면 축소.
