# ADR-0004: 조사 서브에이전트는 데이터 출처별(조회·검색·계산)로 나누고 Send로 필요한 것만 병렬 실행한다

- 상태: Accepted
- 관련: `src/finagent/graph/agents.py`, `graph/nodes.py::dispatch`

## 배경
처음 v2 구현은 노드 하나 안에서 함수 3개를 `asyncio.gather`로 돌렸다. 그래프에도 상자 하나로만 보여 멀티에이전트 구조를 설명할 수 없었다.

## 결정
- 컴파일된 서브그래프 3개를 둔다.
  - `structured_agent`: 조회 → 점검
  - `rag_agent`: 검색 → 선택
  - `calc_agent`: 금리 확보 → 계산 → 점검
- 감독(plan·gate)이 만든 task 목록에 따라 `Send`로 필요한 것만 병렬 호출하고, 결과는 리듀서(`results`)로 합친다.
- `calc_agent`는 금리가 없으면 스스로 조회해서 다른 에이전트를 기다리지 않는다.
- easy 경로도 같은 `rag_agent`를 재사용한다.

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. 단일 노드 + gather | 코드 최소 | 그래프에서 구조가 안 보이고, 에이전트별 재시도·관측 단위가 없음 |
| B. 상품 종류별(예적금/대출/약관) | 도메인 직관적 | 세 에이전트가 같은 조회·계산 도구를 중복 보유, 교차 비교 질문의 소유가 애매함 |
| **C. 데이터 출처별 + Send (채택)** | 도구와 1:1, 질문마다 필요한 에이전트만 실행, 그래프에 내부까지 보임 | 서브에이전트는 결정론 흐름이라 자율성이 낮음 |

## 결과·트레이드오프
- 멀티에이전트는 새 정보(도구 결과)를 가져올 때만 가치가 있다(AI Agents in Depth 10.2). 세 에이전트 모두 도구 결과를 가져오므로 이 기준을 만족한다.
- `calc_agent`가 금리를 직접 조회하므로 조회가 `structured_agent`와 중복될 수 있다(도구 호출 1회 추가).
- 자율 LLM 에이전트가 아니라 결정론 서브그래프다. 재현성과 검증 가능성을 얻는 대신 자율성을 포기했다.

## 재검토 조건
조건 해석이 복잡한 질문("우대조건 없이 가입 가능한 것 중")이 늘면 `structured_agent`에 LLM 도구 호출을 넣는다.
