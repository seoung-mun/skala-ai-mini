# ADR-0009: 베이스라인은 조건을 고정해 한 번 측정하고, 채점이 바뀌면 재채점만 한다

- 상태: Accepted
- 관련: `eval/build_golden.py`, `eval/run_eval.py`, `src/finagent/scoring.py`

## 배경
Before/After 비교는 같은 입력·같은 조건이어야 한다. 그런데 골든셋을 늘리고 채점을 고칠 때마다 베이스라인을 다시 돌렸다. 16GB 노트북에서 매번 수십 분씩 걸렸다.

## 결정
- **동결:** 골든셋 40문항(정답은 실데이터에서 코드로 계산), 데이터 202609 스냅샷, qwen3:8b, `num_ctx=8192`.
- **베이스라인:** 1회 측정해 원본 답변을 저장한다.
- **채점이 바뀌면:** `run_eval.py rescore`로 저장된 v1·v2 답변을 다시 채점한다. 질문이 바뀐 문항이 있으면 재측정이 필요하다고 멈춘다.
- **채점은 코드로 한다.** 비교 질문은 답이 처음 고른 후보로 판정하고, 수치 질문은 질문의 값을 뺀 첫 주장 값으로 판정하며 부정("~가 아니")을 확인한다.

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. 변경 때마다 v1·v2 재측정 | 항상 최신 | 시간·자원 낭비, 결과가 흔들림 |
| **B. 동결 + rescore (채택)** | 비교 기준이 고정됨, 채점 개선이 싸짐 | 골든셋·데이터를 바꾸면 결국 재측정 필요 |

## 결과·트레이드오프
- 40문항은 작다. 정답률 60% 기준 표준오차가 약 ±7.7%p(95% 구간 ±15%p)라 몇 문항 차이는 우연일 수 있다(AI Agents in Depth 7.7). 문항별 짝지은 비교로 해석한다.
- 이번 측정은 노트북 부담 때문에 1회만 했다. 지연시간은 반복 측정이 필요하다.
- 골든셋을 직접 작성했으므로 과적합 위험이 있다.

## 재검토 조건
골든셋을 바꾸거나 모델·데이터 스냅샷을 바꾸면 베이스라인을 다시 동결·측정한다.
