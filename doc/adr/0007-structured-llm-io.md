# ADR-0007: LLM 입출력은 pydantic 모델로 구조화하고, 성공 여부는 ok 키 하나로 표시한다

- 상태: Accepted
- 관련: `src/finagent/schemas.py`, `llm.py`

## 배경
LLM 응답을 자유 텍스트로 받으면 형식 오류가 조용히 넘어간다. 성공·실패 판단이 호출부마다 달라진다.

## 결정
- 입력은 `*Input` 모델(예: `AnswerInput`)로 만들고, `to_prompt()`가 정해진 형식의 읽기 쉬운 텍스트로 렌더링한다.
- 출력은 `*Output` 모델의 JSON Schema로 형식을 강제하고 `model_validate_json`으로 검증한다. 실패하면 `LLMOutputError`로 올린다.
- 모든 출력에 `ok`가 있다. 예를 들어 `AnswerOutput.ok=false`는 "근거 부족"이고, 이때는 재작성하지 않고 부족한 이유를 안내한다.
- 출력 모델은 `extra="forbid"`이고 모든 필드가 필수다.
- 베이스라인(v1)은 비교를 위해 비구조화 그대로 둔다.

## 근거(실측, qwen3:8b)
| 시도 | 결과 |
|---|---|
| 입력을 JSON 덩어리로 전달 + 추가 키 허용 | 모델이 `citations_and_citable_ids_and_...` 같은 긴 키를 지어내다 1,024토큰에서 잘려 형식 오류(응답 4,400자, 지연 160~210초) |
| 추가 키 금지 + 기본값 있는 필드 | `{"ok": true}`만 내고 끝나는 빈 출력(생성 15토큰) |
| **추가 키 금지 + 전 필드 필수 + 텍스트 렌더링 입력 (채택)** | 계산 질문이 1회에 통과, 8.7초, 프롬프트 556토큰 |

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. 자유 텍스트 + 정규식 파싱 | 단순 | 형식 오류가 조용히 넘어감 |
| **B. pydantic 구조화 + ok 키 (채택)** | 형식 오류가 명시적으로 드러나고, 근거 부족을 정상 결과로 표현 가능 | 소형 모델은 스키마 설계에 민감(위 실측) |

## 재검토 조건
OpenAI 같은 강한 모델로 바꾸면 strict 모드 구조화 출력을 켜고 렌더링 형식을 단순화한다.
