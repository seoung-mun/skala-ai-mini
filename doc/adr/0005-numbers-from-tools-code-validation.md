# ADR-0005: 숫자는 도구만 만들고, 답변은 코드가 단위별로 검증한다

- 상태: Accepted
- 관련: `src/finagent/validate.py`, `graph/nodes.py::validate_node`

## 배경
베이스라인은 LLM이 직접 계산해 틀렸다(79,625원 → 147,000원, 506,685원 → 57,000원).
비교 질문에서는 저축은행 상품이나 1위가 아닌 상품을 답했다.

## 결정
- 금리·순위·이자는 MCP 도구 결과만 쓴다.
- validate 노드가 코드로 확인한다.
  1. 답의 `%` 값은 조회 금리·금리표·설명·질문의 `%` 값 안에서만, `원` 값은 계산 결과·입력 금액·설명·질문의 금액 안에서만 허용한다(단위 분리).
  2. 1위를 묻는 질문은 답이 처음 언급한 상품·회사가 조회 1위여야 한다.
  3. 계산 질문은 세전 또는 세후 결과가 답에 있어야 한다.
- 실패하면 반려 사유를 주고 재작성한다(easy 1회, hard 2회). 그래도 실패하면 도구 결과 표로 답한다.
- 원문과 다른 인용은 답을 반려하지 않고 빼되, 뺀 사실을 경고로 남긴다.

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. LLM-as-judge | 표현 이해 | 같은 모델의 자기 검토는 새 정보가 없어 효과가 작음(AI Agents in Depth 10.2), 비용·지연 증가 |
| **B. 결정론 코드 검증 (채택)** | 재현 가능, 비잔틴 실패(그럴듯한 오답)를 독립적으로 잡음 | 의미 오류(속성 혼동: 우대 폭 vs 최고금리)는 못 잡음 |

## 근거·발견한 결함
- 테스트로 찾은 버그: 재작성 시 반려 사유에 적힌 틀린 숫자가 다음 시도에서 "근거"로 인정됐다. 근거는 구조화 입력의 필드에서만 모으도록 고쳤다.
- 리뷰로 재현한 버그: "기본금리 12%"가 기간 12개월 때문에 통과했다. 단위별 허용 집합으로 고쳤다.
- 인용 엄격 반려 정책은 정답을 표 fallback으로 떨어뜨렸다. 인용은 보조 정보라 제외+경고로 바꿨다.

## 결과·트레이드오프
- 숫자 환각을 막는 대신 재작성 때문에 LLM 호출과 지연이 늘 수 있다.
- 검증을 통과하지 못하면 답이 딱딱한 표로 나온다.

## 재검토 조건
속성 혼동 오답이 남으면 질문 의도(어떤 속성을 묻는지)를 슬롯으로 뽑아 해당 값만 허용하도록 좁힌다.
