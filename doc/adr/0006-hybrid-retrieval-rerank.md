# ADR-0006: 검색은 슬롯 필터 + BM25·임베딩 하이브리드 + 상위 후보 리랭킹으로 한다

- 상태: Accepted
- 관련: `src/finagent/retrieval.py`, `graph/agents.py::allowed_ids`

## 배경
표현이 다른 질문("월급 받는 통장", "애 앞으로 드는 적금")을 키워드만으로는 못 찾는다. 베이스라인의 표현 변형 질문 정답률은 50%였다.

## 결정
1. 질문의 상품 종류·은행·상품명으로 후보를 먼저 좁힌다(슬롯 필터).
2. BM25(전체 마크다운)와 KURE-v1 임베딩(embedding 섹션만)을 RRF로 합친다.
3. 상위 5개만 `bge-reranker-v2-m3`(fp16)로 다시 정렬한다. `RERANK=0`으로 끌 수 있다.
4. 임베딩은 내용 해시로 캐시한다.

## 근거(실측, 쉬운 질문 20개)
| 방식 | top-1 | top-3 |
|---|---|---|
| 키워드만(필터 없음, 10문항 기준) | 8/10 | - |
| 하이브리드(필터 없음, 10문항 기준) | 9/10 | - |
| 필터 + 하이브리드 | 18/20 | 20/20 |
| **필터 + 하이브리드 + 리랭커** | **20/20** | 20/20 |

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. 키워드만 | 빠름, 메모리 0 | 표현 변형에 약함 |
| B. 임베딩만 | 의미 검색 | 상품명·은행 정확 매칭이 약함 |
| **C. 필터 + 하이브리드 + 리랭커 (채택)** | 정확 매칭과 의미 검색을 함께 | 메모리(KURE ~1.5GB, 리랭커 ~0.4GB), 첫 색인 47초, 리랭킹 질의당 ~330ms |

## 결과·트레이드오프
- 리랭커 효과는 그 도입 계기가 된 문항(S4, N7)으로 확인했다. 일반화 여부는 전체 측정에서 다른 문항이 나빠지지 않았는지로 판단한다.
- 16GB 노트북에서는 Ollama(약 6GB)와 함께 올리면 메모리가 빠듯하다.

## 재검토 조건
상품 수가 크게 늘면(수만 개) FAISS 근사 색인과 리랭킹 풀 크기를 다시 정한다.
