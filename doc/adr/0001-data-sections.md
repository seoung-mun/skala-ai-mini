# ADR-0001: 공시 데이터를 상품별 마크다운으로 만들고 섹션마다 검색 방식을 표시한다

- 상태: Accepted (2026-10-20)
- 관련: `scripts/fetch_finlife.py`, `scripts/build_data.py`, `src/finagent/parser.py`

## 배경
금감원 「금융상품한눈에」 API 5종(예금·적금·주담대·전세대출·신용대출) × (은행, 저축은행)을 수집하면 988개 상품이 나온다.
금리·기간 같은 정형 값과 우대조건·수수료 같은 자유 텍스트가 한 상품에 섞여 있다.
실데이터를 확인해 보니 다음 문제가 있었다.
- 같은 상품코드를 다른 종류가 함께 쓴다(주담대·전세대출, 신용대출의 마이너스·카드론).
- 주담대 평균금리의 53%(36/68)가 최소~최대 범위 밖이다.
- 종료일 자리에 `99991231`이 들어 있다.

## 결정
상품 1개를 마크다운 1개로 만들고, 섹션마다 `<!-- retrieval: keyword -->` 또는 `<!-- retrieval: embedding -->` 마커를 붙인다.
- 정형 값(이름·금리표·데이터 주의)은 키워드·구조화 조회 대상이다.
- 자유 텍스트(우대조건·수수료)는 임베딩 대상이다.
- 상품 id에는 종류를 붙이고(`saving_202609_...`), 이상치는 `데이터 주의`로 드러낸다.
- 공시 평균금리는 계산·순위에 쓰지 않는다.

## 대안 비교
| 대안 | 장점 | 단점 |
|---|---|---|
| A. 원본 JSON을 그대로 임베딩 | 구현 없음 | 금리표 숫자가 임베딩을 오염시키고 인용 단위가 없음 |
| **B. 상품별 마크다운 + 섹션 마커 (채택)** | v1은 전체 키워드 검색, v2는 embedding 섹션만 색인, 같은 파일로 Before/After 비교 가능 | 988개 파일, 재생성 시 이전 파일 정리 필요 |
| C. 필드 단위 청크 | 검색 정밀 | 주담대 텍스트가 15~61자로 너무 짧아 의미 검색이 약함 |

## 결과·트레이드오프
- v1과 v2가 같은 데이터를 쓰므로 비교가 공정하다. 데이터 표기를 고치면(열 이름 `최고금리(우대 포함)`, `금융권` 행) 베이스라인도 다시 측정해야 한다.
- id 충돌 버그(색인에서 6개 문서가 조용히 빠짐)를 실측으로 찾아 수정했고, 이제 중복 id는 오류로 멈춘다.

## 재검토 조건
약관·상품설명서 PDF 같은 긴 문서를 추가하면 섹션 내부 청킹이 필요하다.
