# 베이스라인(v1) → v2 개선 정리

> 같은 골든셋 40문항 · 같은 데이터(2026년 9월 공시) · 같은 모델(qwen3:8b, temperature 0, num_ctx 8192)로 측정했다.
> v1은 동결값이에요. v2는 지연 최적화([ADR-0011](adr/0011-latency-memory-optimizations.md)) 뒤 2026-10-20에 다시 쟀어요(16GB 노트북, 1회).
> 설계 결정의 근거와 대안은 [ADR 목록](adr/README.md)에 있다.

  - 개선: S2, H1, H2, H3, H6, H7, N7, N9, N11, N13, N15, N16, N18, N20
  - 퇴보: N10
- **최적화 전 v2(87.5%)와의 차이:** S1·S3가 정답으로 바뀌었어요. 하지만 두 문항의 근거 문서는 전후가 같아요. 최적화 효과가 아니라 실행 간 변동으로 봐요(ADR-0011). 최적화 전 수치는 정답률 87.5%, 지연 24.5초 / 37.0초예요.
- **측정 횟수:** 노트북 메모리(16GB) 부담 때문에 1회만 측정했어요. temperature 0이라 정답률은 거의 변하지 않지만, 지연시간은 반복 측정이 필요해요.
- **재현:** `uv run python eval/run_eval.py compare` → [eval/results/compare.md](../eval/results/compare.md). 원본 답변은 `eval/results/{baseline,v2}.jsonl`에 있어요.

## 3. 지연 분석과 최적화

### 3.1 원인 (최적화 전 실측 분해)

v2는 프롬프트가 절반인데도 2배 느렸어요. 쉬운 질문 4개로 단계별 시간을 나눠 쟀어요.

| 단계 (평균) | v1 | v2 (최적화 전) |
|---|---|---|
| 검색 (임베딩 + 리랭킹) | 거의 0 | **20.4초** |
| LLM 프롬프트 처리 | 9.0초 (약 3,400토큰) | 2.1초 (약 1,400토큰) |
| LLM 생성 | 3.1초 (50토큰) | 9.1초 (137토큰) |

- **주원인은 메모리 경합이에요.**
  - Ollama를 내린 상태에서 검색 단계는 안정 시 약 0.1초예요 (질의 임베딩 27ms + 리랭킹 73ms).
  - Ollama(약 6GB)를 올리면 17.9초로 늘어요.
  - 검색 모델을 CPU로 옮겨도 19.4초라 GPU 경합은 아니에요.
  - 측정 중 스왑아웃 카운터가 약 510만 페이지 늘었어요. 16GB에서 LLM 호출과 검색이 번갈아 서로를 스왑으로 밀어내요.
- **부원인은 생성 토큰 증가예요.** JSON 형식과 인용문 때문에 2.7배 늘었어요. 스키마 강제 자체의 속도 손실은 약 8%예요 (16.8 vs 18.2 tok/s).
- **이득:** 필요한 문서만 넣어서 프롬프트 처리는 7초 빨라졌어요.

### 3.2 적용한 최적화 (2026-10-20, [ADR-0011](adr/0011-latency-memory-optimizations.md))

| # | 변경 | 효과 (실측) | 트레이드오프 |
|---|---|---|---|
| 1 | KURE-v1 fp16 로딩, 캐시 키에 dtype 포함 | MPS 할당 3,051MB → 1,129MB. 벡터 코사인 ≥ 0.9997, dense 상위 50위 동일 | 캐시 재생성 1회(약 9.5초), 로딩 순간 CPU 메모리가 잠깐 오름 |
| 2 | 상품명이 정확히 매칭되면 검색 생략 | 해당 19문항 지연 중앙값 25.9초 → **10.6초**. 결과가 같음이 코드로 보장됨 | 상품명 매칭이 틀리면 검색 보완이 없음(이전에도 같은 한계) |
| 3 | RRF 후보 ≤ k면 리랭킹 생략 | 해당 2문항(N1·N9) 30.6초 → 17.2초, 24.7초 → 15.6초. 둘 다 정답 유지 | 근거 순서가 RRF 순서로 남음 |

**누적 ablation** (쉬운 질문 E1·N2·S2·N8, Ollama 로드 상태, 각 1회, 4문항 평균)

| 변경 | 검색 ms | 총 지연 s | 스왑아웃 페이지 |
|---|---|---|---|
| 변경 전 | 19,670 | 40.7 | 3.10M |
| + KURE fp16 | 7,811 | 24.1 | 1.68M |
| + 상품명 매칭 시 검색 생략 (2회 측정) | 7,505 / 6,458 | 36.2 / 21.4 | 2.62M / 1.39M |
| + 후보 ≤ k면 리랭킹 생략 (이 4문항에서는 발동 안 함) | 7,719 | 31.1 | 2.47M |

- 측정 중 시스템 스왑 사용량이 12.7GB에서 20GB까지 찼어요(브라우저 등 포함). 같은 설정을 다시 재도 총 지연이 21~36초로 흔들렸어요.
- 그래서 ablation은 방향만 보고, 효과는 전체 골든셋 측정의 문항 그룹별 중앙값으로 판단했어요.

**전체 측정 결과 (40문항, 그룹별 지연 중앙값)**

| 그룹 | 최적화 전 | 최적화 후 |
|---|---|---|
| 상품명 매칭 (19문항) | 25.9초 | **10.6초** |
| 검색이 필요한 쉬운 질문 (8문항) | 32.6초 | 34.1초 |
| 그 밖의 문항 (13문항) | 11.9초 | 12.5초 |
| **전체 중앙값 / p90** | 24.5초 / 37.0초 | **13.4초** / 38.8초 |

- **나아진 점:** 중앙값이 v1(11.3초)에 가까워졌어요. 거의 전부 2번(검색 생략) 덕분이에요. 검색 모델을 깨우지 않으니 LLM 호출도 스왑에 덜 밀려요.
- **나아지지 않은 점:** 표현 변형처럼 검색이 꼭 필요한 질문은 여전히 30초대예요. p90도 그대로예요.
  - 마지막 측정에서 이 질문들의 검색은 인코딩 약 7.7초 + 리랭킹 약 7.6초였어요. 모두 Ollama 호출 직후의 스왑인 비용이에요.
- **검토했지만 넣지 않은 것:**
  - 인용 생성을 조건 질문으로 제한하는 안은 계약의 `citations`를 UI가 근거로 쓰고, 스키마에 이미 "없으면 빈 배열"이 있어 넣지 않았어요.
  - `RERANK=0`은 S4·N7 top-1 회귀가 있어 넣지 않았어요(ADR-0006).
- **다음 후보:**
  1. 검색 모델을 별도 상주 프로세스로 분리하거나 Ollama 임베딩으로 옮겨요.
  2. 메모리가 넉넉한 환경이나 `LLM_BACKEND=openai`에서 같은 골든셋으로 다시 재요.

## 4. 남은 오답 분석

| 문항 | 유형 | 원인 |
|---|---|---|
| E2, S4, N10 | 속성 혼동 | "우대금리 최대 몇 %p"(우대 폭, 설명 원문)를 "우대 포함 최고금리"(금리표)로 답함. 두 숫자 모두 근거에 있어 코드 검증을 통과함 |

- 최적화 전 측정의 오답 S1(검증 실패 → fallback)과 S3(속성 혼동)는 재측정에서 정답이 됐어요.
  - 다만 S3 답변은 "최고 연 6.0%"와 "최고금리 6.70%"를 함께 말해요. 첫 주장 값으로 정답 처리된 것이라 속성 혼동은 그대로 남아 있어요.

- **표현 변형 질문이 75%에 머무는 이유:** 검색은 개선됐어요 (top-1 20/20). 하지만 남은 오답이 모두 속성 혼동이에요.
- **다음 개선:** 질문이 묻는 속성(우대 폭 / 기본금리 / 최고금리)을 슬롯으로 추출하고, 검증에서 그 속성의 값만 허용해요 ([ADR-0005](adr/0005-numbers-from-tools-code-validation.md) 재검토 조건).

## 6. 한계와 트레이드오프 요약

- **정확도 vs 지연:** 정답률 +32.5%p를 얻었어요. 최적화 후 지연 중앙값은 v1의 1.2배까지 줄었지만, 검색이 필요한 질문의 p90은 v1의 2.3배예요 (16GB 메모리 경합이 주원인).
- **결정론 vs 자율성:** 숫자·순위는 코드로 보장하지만, 서브에이전트가 자율적으로 판단하지는 않아요.
- **코드 검증의 한계:** 근거에 있는 다른 숫자를 고르는 속성 혼동은 못 막아요.
- **평가의 한계:**
  - 골든셋 40문항은 직접 작성했어요. 정답은 실데이터에서 코드로 계산했지만 질문 분포는 작성자 편향이 있어요.
  - 1회 측정이에요.
  - 채점의 부정 표현 탐지는 "~가/이 아니" 패턴만 잡아요.
- **데이터의 한계:**
  - 2026년 9월 공시 스냅샷이에요.
  - 실제 적용 금리는 개인 조건에 따라 달라요.
  - 주담대 평균금리의 53%가 범위 밖이라 쓰지 않아요.
