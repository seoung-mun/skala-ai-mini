## 3. 지연이 늘어난 이유 (실측 분해)

v2는 프롬프트가 절반인데도 2배 느려요. 쉬운 질문 4개로 단계별 시간을 나눠 쟀어요.

| 단계 (평균) | v1 | v2 |
|---|---|---|
| 검색 (임베딩 + 리랭킹) | 거의 0 | **20.4초** |
| LLM 프롬프트 처리 | 9.0초 (약 3,400토큰) | 2.1초 (약 1,400토큰) |
| LLM 생성 | 3.1초 (50토큰) | 9.1초 (137토큰) |

- **주원인은 메모리 경합이에요.**
  - Ollama를 내린 상태에서 검색 단계는 안정 시 약 0.1초예요 (질의 임베딩 27ms + 리랭킹 73ms).
  - Ollama(약 6GB)를 올리면 17.9초로 늘어요.
  - 검색 모델을 CPU로 옮겨도 19.4초라 GPU 경합은 아니에요.
  - 측정 중 스왑아웃 카운터가 약 510만 페이지 늘었어요. 16GB에서 LLM 호출과 검색이 번갈아 서로를 스왑으로 밀어내요.
- **부원인은 생성 토큰 증가예요.** JSON 형식과 인용문 때문에 2.7배 늘었어요. 스키마 강제 자체의 속도 손실은 약 8%예요 (16.8 vs 18.2 tok/s).
- **이득:** 필요한 문서만 넣어서 프롬프트 처리는 7초 빨라졌어요.

**개선 계획 (다음 커밋):**
1. KURE를 fp16으로 로딩해요 (약 2.2GB → 약 1.1GB 예상).
2. 상품명이 정확히 매칭되면 검색을 생략해요.
3. 후보가 3개 이하면 리랭킹을 생략해요.
4. 메모리가 넉넉한 환경(또는 `LLM_BACKEND=openai`)에서 다시 측정해요.

## 4. 남은 오답 분석

| 문항 | 유형 | 원인 |
|---|---|---|
| E2, S3, S4, N10 | 속성 혼동 | "우대금리 최대 몇 %p"(우대 폭, 설명 원문)를 "우대 포함 최고금리"(금리표)로 답함. 두 숫자 모두 근거에 있어 코드 검증을 통과함 |
| S1 | 검증 실패 → fallback | 두 번 모두 검증 통과 실패로 상품명만 안내 (v1은 정답) |

- **표현 변형 질문이 50%에서 그대로인 이유:** 검색은 개선됐어요 (top-1 20/20). 하지만 남은 오답이 모두 속성 혼동이에요.
- **다음 개선:** 질문이 묻는 속성(우대 폭 / 기본금리 / 최고금리)을 슬롯으로 추출하고, 검증에서 그 속성의 값만 허용해요 ([ADR-0005](adr/0005-numbers-from-tools-code-validation.md) 재검토 조건).

| 결함 | 발견 방법 | 영향 |
|---|---|---|
| 상품코드 중복으로 색인에서 6개 문서가 조용히 빠짐 | 문서 수 대조 (982 vs 988) | id에 종류 추가, 중복 시 오류 |
| 신용대출 키가 대출종류 없이는 유일하지 않음 | 실데이터 프로브 | 앞서 "항등식 4칸 불성립"이라 한 분석이 오류였음을 확인 |
| 재작성 시 반려 사유에 적힌 틀린 숫자가 근거로 인정됨 | 단위 테스트 | 근거를 구조화 입력에서만 수집 |
| "기본금리 12%"가 기간 12개월 때문에 검증 통과 | 외부 리뷰 재현 | 단위별 허용 집합 |
| "2.45%가 아니라 99.9%"가 정답 처리 | 외부 리뷰 재현 | 첫 주장 값 + 부정 표현 채점 |
| 평균금리(avg) 순위 조회 가능 | 외부 리뷰 재현 | 도구 단 metric 허용 목록 |
| POST·스트림 입력 검증 불일치 | 외부 리뷰 재현 | 공통 검증 함수, 계약 형식 400 |
| 비교 채점이 일반명("정기예금")을 첫 후보로 오판 | 결과 대조 | 채점 후보에서 일반명 제외 |
| LLM이 정의되지 않은 긴 키를 생성하다 잘림 / 빈 출력 | 실모델 점검 | `extra="forbid"`, 전 필드 필수 |
| `num_ctx=16384`로 노트북 끊김 (Ollama 7.4GB) | 사용자 보고 + `ollama ps` | 8,192로 축소, 초과 시 오류 |

## 6. 한계와 트레이드오프 요약

- **정확도 vs 지연:** 정답률 +27.5%p를 얻은 대신 지연이 2배가 됐어요 (16GB 메모리 경합이 주원인).
- **결정론 vs 자율성:** 숫자·순위는 코드로 보장하지만, 서브에이전트가 자율적으로 판단하지는 않아요.
- **코드 검증의 한계:** 근거에 있는 다른 숫자를 고르는 속성 혼동은 못 막아요.
- **평가의 한계:**
  - 골든셋 40문항은 직접 작성했어요. 정답은 실데이터에서 코드로 계산했지만 질문 분포는 작성자 편향이 있어요.
  - 1회 측정이에요.
  - 채점의 부정 표현 탐지는 "~가/이 아니" 패턴만 잡아요.
- **데이터의 한계:**
  - 2026년 9월 공시 스냅샷이에요.
  - 실제 적용 금리는 개인 조건에 따라 달라요.
  - 주담대 평균금리의 53%가 범위 밖이라 쓰지 않아요.
