# OpenAI 베이스라인 5회 평가 규약 — 2026-10-21 동결

상태: 실행 전 확정. 현재 버전은 이번에 실행하지 않는다. 이후 비교는 아래 규약과 저장된 입력을 그대로 사용한다. 규약 변경 시 별도 실험으로 분리하며 기존 응답을 덮어쓰지 않는다.

## 1. 비교 대상과 입력

- 모델: `gpt-4.1-mini-2025-04-14`, OpenAI 공식 Chat Completions, LangChain ChatOpenAI, temperature=0, 동시성 1. 같은 모델 스냅샷을 나중의 현재 버전 평가에도 사용한다. 과거 `gpt-4.1-mini` 별칭 1회 결과와 별도 실험이다.
- 베이스라인: 기존 `run_baseline`, BM25 키워드 top-5 → 비구조화 LLM 1회. 라우팅·도구·검증·재작성·대화 메모리를 추가하지 않는다. 서비스 API와 LangGraph는 변경하지 않는다.
- 골든셋: 기존 43문항, 파일 순서 그대로 회차 1~5를 순차 실행(215 관측). 회차·문항 사이 대화 상태 없음. 로컬 응답 캐시 없음. OpenAI 서버 프롬프트 캐시는 통제하지 않으며 실제 cached_tokens를 별도 기록한다.
- 실행 전 `snapshot/`에 전체 Python 소스, 상품 마크다운 988개, 골든셋, 의존성 lock, 규약, 실행 스크립트를 복사하고 파일별 SHA-256을 manifest에 기록한다. 실행은 이 소스·상품 사본에서 진행한다. 인증 파일은 복사하지 않고 앱의 설정 로더만 사용한다.
- 후속 질문(setup 포함)도 베이스라인에는 query만 준다. 이는 기존 baseline 평가의 메모리 부재 조건이다. 추후 현재 버전은 기존 run_eval대로 setup을 별도 실행·추적하고 질문의 지연/토큰과 setup 지연/비용을 각각 보고한다. 두 시스템의 정보 차이는 기능 차이이며 이 하위집합은 별도 표시한다.

## 2. 채점

- 동결된 `scoring.py`와 그 의존 코드로 결정론적으로 채점한다. LLM judge와 사람의 사후 정답 변경은 없다. 숫자/단위·첫 주장·상품명·순위·거절·nonempty 등 각 문항의 기존 check를 그대로 적용한다.
- S3는 기존 6.0(%p 우대 폭) 기준 그대로다. 질문의 '최대 몇 %'는 최고금리 6.7%와 혼동 여지가 있으므로 결과 해석에 명시한다. 문항을 보고 기준을 바꾸거나 이번 원본을 재채점하지 않는다.
- 주 지표: 전체 215개 정답 수/215, 회차별 정답 수/43 및 5회 정답률의 평균·표본 표준편차. 문항별 0~5회 성공과 난이도·범주별 정답률, 검색 적중률을 보조 보고한다.
- API 실패도 215개 분모에 포함하여 오답 처리한다. 실패율·성공 응답 기준 정답률도 별도 표기한다. 채점기의 문자열/숫자 휴리스틱을 통과했다는 뜻이며 금융 답변 전체의 의미적 정확도를 보증하지 않는다.

## 3. 지연·비용·오류

- 지연: perf_counter로 색인 준비가 끝난 뒤 baseline 함수 진입 직전부터 답변 반환(또는 실패)까지 측정한다. 검색·네트워크·모델 생성·SDK 내부 재시도·호출 중 추적 오버헤드를 포함한다. 초기 색인 생성·앱 시작·채점·LangSmith 원격 조회·브라우저/HTTP/SSE 렌더링은 제외한다. 첫 질문도 포함하며 별도 유료 warmup은 없다.
- 215개 관측의 중앙값·p90·p95·최대와 회차별 중앙값/p90을 보고한다. 분위수는 오름차순 floor(p*(n-1)) 위치 값이다. 문항별 5회 중앙값을 먼저 구한 43개 분포는 기존 summarize와 호환되는 보조 지표로 분리한다. 실패를 지연에서 삭제하지 않는다.
- 어댑터/SDK의 기존 timeout·retry 설정을 변경하지 않고 실행 시 유효 값과 패키지 버전을 manifest에 기록한다. SDK 내부 HTTP 재시도 횟수는 계측하지 않아 0회라고 주장하지 않는다. 평가기가 별도로 오답/실패를 재호출하지 않는다.
- 비용 주 지표(비교용): 입력 $0.40/1M, 출력 $1.60/1M로 모든 입력을 일반 단가 처리한 토큰 기준 추정 USD. 회차별·전체·문항당을 집계하며 합산 전에 개별 반올림하지 않는다. 캐시 반영 추정치는 cached input $0.10/1M로 따로 계산한다. 실제 청구액, LangSmith 요금, 로컬 컴퓨팅 비용은 아니다.
- 실패 중 사용량이 회수되지 않으면 null로 남기며 비용 누락 건수를 표시한다. 중단 시 원본/시도 기록은 보존하고 임의로 빠른 재시도 결과로 대체하지 않는다. 정상 종료한 파일의 재실행은 거부한다. 중단 복구는 저장된 (문항 ID, 회차)를 건너뛰되 미완료 시도를 명시한 별도 복구 절차로 수행한다.

## 4. 추적·보존·후속 비교

- LangSmith `finagent` 프로젝트. root 이름 `baseline / 회차 N / ID`; metadata `item_id`, `repeat`(1~5), `system`, `batch_id`, `model`, `protocol_sha256`; 같은 정보를 태그에도 기록한다. 기존 JSONL 호환 repeat는 0~4이며 화면용 repeat_number는 1~5다.
- 매 문항 답변·검색 ID·정오답·토큰·cached tokens·요청/응답 모델·지연·root run ID를 즉시 JSONL에 저장한다. 실행 전 시도도 attempts.jsonl에 기록한다. 종료 후 원격에서 root 완료와 metadata, LLM 자식 span을 조회해 검증하고 실제 링크를 저장한다. 전송 대기만으로 추적 성공이라 하지 않는다.
- 이후 현재 버전 평가 전 골든셋/상품/채점기/모델/단가/회차/순서의 동일성을 확인한다. 개선된 그래프 소스는 별도 동결하고 차이를 기록한다. 문항·회차를 짝지어 정답 변화와 비용/지연 변화를 계산한다. 현재 버전의 도구 및 검증/재작성은 해당 trace에서 별도 분석한다.
- 43개는 개발 중 오류 분석에 이미 사용한 골든셋이다. 5회 반복은 같은 문항에 대한 변동 측정이며 새로운 215문항이나 미공개 테스트셋 일반화 성능이 아니다. 두 시스템을 다른 시간에 실행하므로 네트워크/서버 부하에 따른 지연 교란이 남는다. 일반화 평가는 별도 미공개 문항이 필요하다.

근거(2026-10-21 확인): [OpenAI 모델 스냅샷과 단가](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [LangSmith metadata/tags](https://docs.langchain.com/langsmith/add-metadata-tags). 로컬 평가 세부 규칙과 5회 선택은 본 프로젝트의 사전 확정 규약이다.
